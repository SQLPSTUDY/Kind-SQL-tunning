# 통계정보와 비용 계산 원리

## 선택도와 카디널리티

- `선택도 = 1 / NVD`
    - 선택도 : 전체 레코드 중 조건절에 의해 선택되는 레코드 비율
    - NVD(Number of Dinstinct Value) : 컬럼 값 종류 개수
- `카디널리티 = 총 로우 수 * 선택도 = 총 로우 수 / NDV`
    - 전체 레코드 중 조건절에 의해 선택되는 레코드 수

### 통계정보

- 오브젝트 통계
    - 테이블 통계 : `dbms_stats.gather_table_stats()` , `all_tab_statistics` 뷰에서 확인
    - 인덱스 통계 : `dbms_stats.gather_index_stats(ownname => '', indname => '')` , `all_ind_statistics` 뷰에서 확인
    - 컬럼 통계 : 테이블 통계 수집시 함께 수집, `all_tab_col_statistics` 뷰에서 확인
- 시스템 통계 : 애플리케이션 및 하드웨어 성능 특성, `sys.aux_stats$` 뷰에서 확인

## 비용 계산 원리

- 인덱스 수직적 탐색 비용 + 인덱스 수평적 탐색 비용 + 테이블 랜덤 액세스 비용
- 인덱스 키값이 모두 등호 조건
    
    ```
    비용 = BLEVEL
    		+ AVG_LEAF_BLOCKS_PER_KEY
    		+ AVG_DATA_BLOCKS_PER_KEY
    ```
    
- 인덱스 키값이 모두 부등호 조건
    
    ```
    비용 = BLEVEL
    		+ AVG_LEAF_BLOCKS_PER_KEY * 유효 인덱스 선택도
    		+ AVG_DATA_BLOCKS_PER_KEY * 유효 태이블 선택도
    ```
    

# 옵티마이저에 대한 이해

`비용 기반 옵티마이저` : 사용자 쿼리를 위해 후보군이 될만한 실행계획들을 도출하고 데이터 딕셔너리에 미리 수집해 둔 통계정보를 이용해 각 실행계획의 예상비용을 산정 후 그 중 가장 낮은 비용의 실행계획 하나를 선택

## 옵티마이저 모드

- ALL_ROWS : 전체 처리속도 최적화
- ~~FISRT_ROWS : 최초 처리속도 최적화~~
- FISRT_ROWS_N : 최초 N건 응답속도 최적화

## 옵티마이저에 영향을 미치는 요소

- SQL과 연산자 형태
- 인덱스, IOT, 클러스터, 파티션, MV 등 옵티마이징 팩터
- 제약 설정
- 통계 정보
- 옵티마이저 힌트
- 옵티마이저 관련 파라미터

### 개발자의 역할

- 필요한 최소 블록만 읽도록 쿼리 작성
- 최적의 옵티마이징 팩터 제공
    - 전략적인 인덱스 구성
    - DBMS가 제공하는 다양한 기능 활용
    - 옵티마이저 모드 설정
    - 정확하고 안정적인 통계정보
- 필요하다면 옵티마이저 힌트를 사용해 최적의 액세스 경로 유도
